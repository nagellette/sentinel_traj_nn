# Knowledge curation

1. Review recent relevant worklogs, `vault/notes/`, and current source/code.
2. Identify durable facts, repeated patterns, decisions, and outdated information.
3. Verify against project files and observed results; label unknowns.
4. Propose concise changes to `vault/kb/` and `vault/INDEX.md`; link source worklogs.
5. Mark superseded decisions rather than deleting historical rationale.
6. Prune stale, duplicated material while preserving important context. Never preserve raw sensitive chat content.
7. Update state/tasks only if this changes the next action.
